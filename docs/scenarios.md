# 지원 목표·시연·검증

갱신한 PRD의 P0 기능을 다섯 앱에 걸쳐 나눈다. 라이브 A·B에서 먼저 통합할 흐름과 다섯 앱 모두에 대한 기능 완료는 따로 기록한다. 사용자 조작과 Zoro-1 판단을 모두 검증한다. 아래 메뉴는 AVD 한국어 UI에서 확인할 후보이며 앱 업데이트에 따라 고친다.

| 목표 ID | 앱 · P0 목표 | 슬롯 | 대표 후보와 완료 증거 |
|---|---|---|---|
| SET_FONT | 설정 · 글자 크게 하기 | 필요 시 +1단계 | 홈 설정 → 디스플레이 → 표시 크기 및 텍스트. 글자 메뉴와 큰 쪽 조절 영역 안내. 선택 단계/미리보기 변화를 직접 확인 |
| SET_TIMEOUT | 설정 · 화면 꺼짐 시간 늘리기 | 예시 10분 | 디스플레이에서 화면 자동 꺼짐 메뉴 열기 → 10분 선택. 실제로 10분 선택이 반영된 설정 화면 확인 |
| CLOCK_ALARM | 시계 · 알람 맞추기 | 날짜 의미, 시각, 오전/오후 | 알람 탭 → 추가 → 오전 6:00 → 저장 → 활성 알람 카드. 「내일」은 다음 예정 시각이 실제로 내일인지 확인 |
| MAP_ROUTE | Google 지도 · 목적지 길찾기 | 공개 장소 이름 | 검색창 → 목적지 입력 → 일치 항목 → 길찾기. 목적지와 경로 화면 표시를 확인 |
| SMS_SEND | 메시지 · 문자 보내기 | 시연 수신자, 시연 문구 | 새 대화 → 승인된 상대 → 내용 입력 → 보내기 위치 안내. 사용자가 보내고 발신 상태 확인, 별도 AVD 수신 확인 |
| MAIL_OPEN | Gmail · 받은 메일 열기 | 시연 메일 식별 정보 | 받은편지함 → 미리 준비한 메일 카드 → 상세. 메일 본문·주소를 서버에 보내지 않고 열림 증거만 보냄 |

슬라이더를 끄는 안내는 PRD C-7의 P1이다. SET_FONT는 해당 AVD에서 터치로 바로 선택하는 +/− 또는 조절점을 우선 확인한다. 드래그만 가능한 화면이라면 조절 위치까지 안내하고, 부모의 직접 조작에 의한 완료를 기록한다. 드래그 안내를 P0 완료로 표시하지 않는다. 실제 UI가 이 가정과 다르면 첫 환경 검증에서 지원 방식과 통과 범위를 고친다.

## 라이브 A · 막혔을 때만 끼어들기

사전 준비에서 Settings 한국어 레이아웃으로 표시 대상, 잘못 선택할 항목, 아래쪽으로 숨길 대상과 역엣지를 각각 확인한다. 메뉴 라벨이 AVD에서 다르면 같은 분기를 발생시키는 해당 버전의 검증 가능한 메뉴를 택해 실행 기록에 고정한다.

| 단계 | 입력 및 실제 조작 | 기대 결과 |
|---|---|---|
| A1 | 부모 AVD 발신, 자녀 AVD 수락. 부모가 설정 화면을 열고 자녀가 “디스플레이 눌러 줘”라고 말함 | 자녀 확정문으로 3초 시작. 첫 자녀 지시/목표에만 이어폰 예외를 적용한 스피커 전환 |
| A2 | 3초 안에 디스플레이 진입 | 테두리·복구 문구 0회. 새 화면에서 다음 행동을 알아서 표시하지 않음 |
| A3 | 자녀가 “화면 자동 꺼짐을 눌러 줘”라고 하고 부모가 다른 검증 메뉴를 엶 | 모델 WRONG + 검증된 역엣지 확인. 3초 후 “뒤로 가기” 표시. 직접 돌아감 |
| A4 | 돌아온 화면에서 지시 대상이 아래에 가려져 있는 상태에서 “화면 자동 꺼짐을 눌러 줘”라는 새 지시 | 새 t0. 부모님의 응답에는 타이머 변경 없음. 3초 이후 “화면 내리기”. 직접 스크롤 |
| A5 | 같은 지시가 유효할 때 대상을 실제로 노출시키고, 정해진 조건에서 3초가 지난 상태로 누르지 않음 | 마지막 지시 대상 한 곳에 빨간 테두리. 직접 탭하면 사라짐. 자녀 UI에 지시/진행 전송 없음 |

실험 중 자녀 지시가 없는 상태의 무표시, 같은 위치를 잘못 인식해 다른 버튼 위에 표시하지 않는지, 새 지시가 기존 타이머를 취소하는지를 함께 확인한다. SET_FONT와 SET_TIMEOUT의 완료 상태는 아래 별도 기능 표본에서 확인한다.

## 라이브 B · 통화 후 알람 안내 이어받기

| 단계 | 입력 및 실제 조작 | 기대 결과 |
|---|---|---|
| B1 | 딸 “엄마, 내일 오전 6시로 알람 맞추자. 시계 앱을 눌러 줘” | CLOCK_ALARM 목표와 첫 지시를 기록. 지시의 버튼 위치를 준비. 다단계 큐는 사용하지 않음 |
| B2 | 부모가 시계 앱을 직접 열고 딸이 통화 종료 | RTC와 STT 종료. 같은 help_id에서 mode_revision 증가, 오래된 통화 중 지시·타이머 취소. 화면 관찰 및 제어는 유지 |
| B3 | 새 안정 화면에서 Agent가 다음 동작을 결정하고 부모가 오전 6시를 직접 선택·저장 | 의미 화면마다 3초 후 현재 한 행동을 안내. 날짜·시각·활성 카드가 일치하면 도착 추정 |
| B4 | 딸이 도착 추정을 보고 완료 버튼 누름 | 도착 추정 알림 한 건. 명시적 완료 후 부모 완료 문구와 도움 기록 삭제 |

에뮬레이터의 날짜, 시간대와 알람의 실제 다음 울림 시간을 확인한다. 통화 후 음성 재수집이나 RTC 재연결을 안내의 전제조건으로 삼지 않는다.

## 나머지 목표와 재현 조건

- SET_FONT는 글자 크기 값/미리보기 변화, SET_TIMEOUT은 10분 선택 상태를 별도 검증한다.
- MAP_ROUTE는 공개 시연 목적지와 정상 네트워크를 사용한다. 후보가 여럿이면 확인하고 길찾기 화면까지 기록한다.
- SMS_SEND는 승인된 시연 상대와 문구를 사용한다. 보내기 UI와 별도 AVD 수신 성공은 따로 기록한다. [에뮬레이터 문자 시뮬레이션](https://developer.android.com/studio/run/emulator-networking-voice)
- MAIL_OPEN은 시연 계정의 받은편지함에 준비된 메일을 연다. 로그인, 권한 대화상자 등에서 보호 규칙을 확인한다. 목록 및 본문을 서버로 전송하지 않는다.
- 사진 공유와 메일 초안은 P1 후보로 남긴다. 기능·장치에서 실제로 검증한 결과와 시험 주입을 구분한다.

## 검증 표본과 티켓

라이브 A/B의 완주 기준, 지시 이해도 17/20, 위치 찾기 85%, 올바른 조작까지 3초 이내에 표시 0회 등 정확한 분모와 기대값은 [실험 계획](verification-plan.md)에 있다.
