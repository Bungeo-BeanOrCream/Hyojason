# 지원 목표·시연·검증

PRD v2의 P0 기능을 다섯 앱에 걸쳐 나눈다. 라이브 A·B에서 먼저 통합할 흐름과 다섯 앱 모두에 대한 기능 완료는 따로 기록한다. 사용자 조작과 Zoro-1 판단을 모두 검증한다. 아래 메뉴는 AVD 한국어 UI에서 확인할 후보이며 앱 업데이트에 따라 고친다.

| 목표 ID | 앱 · P0 목표 | 슬롯 | 대표 후보와 완료 증거 |
|---|---|---|---|
| SET_FONT | 설정 · 글자 크게 하기 | 필요 시 +1단계 | 홈 설정 → 디스플레이 → 표시 크기 및 텍스트. 글자 메뉴와 큰 쪽 조절 영역 안내. 선택 단계/미리보기 변화를 직접 확인 |
| SET_TIMEOUT | 설정 · 화면 꺼짐 시간 늘리기 | 예시 10분 | 디스플레이에서 화면 자동 꺼짐 메뉴 열기 → 10분 선택. 실제로 10분 선택이 반영된 설정 화면 확인 |
| CLOCK_ALARM | 시계 · 알람 맞추기 | 날짜 의미, 시각, 오전/오후 | 알람 탭 → 추가 → 오전 6:00 → 저장 → 활성 알람 카드. 「내일」은 다음 예정 시각이 실제로 내일인지 확인 |
| MAP_ROUTE | Google 지도 · 목적지 길찾기 | 공개 장소 이름 | 검색창 → 목적지 입력 → 일치 항목 → 길찾기. 목적지와 경로 화면 표시를 확인 |
| SMS_SEND | 메시지 · 문자 보내기 | 시연 수신자, 시연 문구 | 새 대화 → 승인된 상대 → 내용 입력 → 보내기 위치 안내. 사용자가 보내고 발신 상태 확인, 별도 AVD 수신 확인 |
| MAIL_OPEN | Gmail · 받은 메일 열기 | 시연 메일 식별 정보 | 받은편지함 → 미리 준비한 메일 카드 → 상세. 메일 본문·주소를 서버에 보내지 않고 열림 증거만 보냄 |

슬라이더를 끄는 안내는 PRD C-7의 P1이다. SET_FONT는 해당 AVD에서 터치로 바로 선택하는 +/− 또는 조절점을 우선 확인한다. 드래그만 가능한 화면이라면 조절 위치까지 안내하고, 부모의 직접 조작에 의한 완료를 기록한다. 드래그 안내를 P0 완료로 표시하지 않는다. 실제 UI가 이 가정과 다르면 첫 환경 검증에서 지원 방식과 통과 범위를 고친다.

## 라이브 A · 설정 목표를 통화 중 바꾸기

| 단계 | 입력/실제 조작 | 기대 결과 |
|---|---|---|
| A1 | 부모가 연결된 자녀 사진을 누르고 자녀가 받음 | 동일 pair 예약. 양쪽 음성 연결, 부모에게 듣고 있다는 상태 표시 |
| A2 | “폰 글씨가 너무 작아.” / “크게 하면 돼.” | 양쪽 SET_FONT. 스피커폰 전환은 이어폰 연결 상태 확인 후 적용 |
| A3 | 부모 홈 → 설정 → 디스플레이 → 표시 크기 및 텍스트 | 각 화면에서 직전 표시가 사라지고 안정된 새 화면에 3초 뒤 대상 하나 표시 |
| A4 | “근데 글 읽는 중에 화면이 꺼져. 10분으로 늘리자.” | Zoro-1 change=yes, SET_TIMEOUT 수정. 정정 종료 후 5초 내 양쪽 목표 표시가 목표 |
| A5 | 부모가 이전에 지나온 디스플레이로 뒤로 가고 10분 선택 | 최신 전이와 최근 방문을 기준으로 BACK → 화면 자동 꺼짐 안내. 화면에 10분이 실제로 반영됨 |
| A6 | 자녀가 “완료된 것 같아요”를 보고 도움 완료 누름 | 부모 “다 됐어요!” 잠깐 노출. 도움과 원본/진행기록 정리, 통화 상태는 독립 |

A4 직전에 A3의 늦은 모델 결과를 테스트 환경에서 주입해도 이전 표시가 나타나지 않아야 한다. A는 시연 중 SET_FONT를 **완료하지 않고 정정하는 장면**이다. SET_FONT 완료는 단독 검증을 한 번 더 해야 P0 지원 완료로 기록한다.

## 라이브 B · 통화가 끝난 뒤 알람 완료

| 단계 | 입력/실제 조작 | 기대 결과 |
|---|---|---|
| B1 | 부모 “내일 아침 6시에 알람 맞추고 싶어” | CLOCK_ALARM의 시간·다음 날 의미를 확정하고 양쪽 목표 표시 |
| B2 | 자녀가 직접 통화 끊기 | RTC 종료, STT 중단. 부모 캡처·안내와 자녀의 도움 완료 버튼은 동일 help_id로 유지 |
| B3 | 부모가 시계에서 오전 6:00을 직접 선택·저장 | 기존 목표로 한 단계씩 안내. 알람 카드와 활성 상태, 예상 울림 날짜를 검증 |
| B4 | 자녀 완료 추정 수신 후 도움 완료 | 추정 알림의 중복 없음. 아직 도움 중일 때만 완료 명령을 받아 부모 완료 표시와 삭제 |

AVD의 시계와 타임존, 알람 목표의 날짜를 리허설 전에 맞춘다. 내일이 아닌 알람을 저장하면 모델이 완료라고 하더라도 로컬 검증에서 보류한다. 종료 후 사용자의 새 음성을 캡처하거나 기존 RTC 연결을 다시 열지 않는다.

## 기타 목표와 실패 처리

- MAP_ROUTE는 준비한 검색어와 정상 네트워크가 있어야 한다. 검색 결과가 다수이면 사용자 확인 또는 화면의 현재 대상 기다림. 지도 도착은 GPS 이동이 아니라 목적지의 길찾기 화면까지다.
- SMS_SEND는 양쪽 AVD의 메시지 앱에서 시험한다. 수신자의 콘솔 포트는 시연 전 확인한다. 시연 번호 외의 실제 번호, 코드 전달, 모르는 링크는 안내하지 않는다. 전송 UI 도달과 AVD 수신을 별개로 기록한다. [에뮬레이터 문자 시뮬레이션](https://developer.android.com/studio/run/emulator-networking-voice)
- MAIL_OPEN은 받은편지함을 사전에 준비한다. 시스템 권한, 로그인, 계정 선택 화면이 감지되면 관찰 및 안내를 보류한다. 테스트 메일의 상세가 열린 것만 확인한다.
- 잘못된 화면, 화면 차단, 음성 불명확, 모델 장애는 각각 로그에서 구분한다. 필요하면 발화로 수동 안내를 계속하되 자동 Overlay 성공으로 세지 않는다. 통화 종료 후 자녀 음성 안내는 사용할 수 없으므로 부모 화면에 기다림 상태를 표시한다.
- 사진 공유 및 Gmail 초안은 이전 기획의 데모다. 현재 기준 Gmail 목표는 받은 메일 열기이고, 사진 보내기는 PRD v2에 따른 P1 후보로 남긴다.

## 검증 표본과 티켓

| 검증 ID | 입력 | 성공 판정 |
|---|---|---|
| V-01 | A·B 각각 5회 | PRD 목표 각각 4/5 이상 완주. 실패 단계와 사용한 모델 경로 기록 |
| V-02 | 20개 발화, 모호함·잘못 인식·정정 포함 | 지원 목표·필수 슬롯·변경 범위 포함 17/20 이상. 보류·거부를 별도 분류 |
| V-03 | 5개 앱의 정답 대상 및 정상 완료 상태 | 정해진 단계 기준 맞는 표시에 85% 목표. 실제 재현한 앱별 버전과 대상만 보고 |
| V-04 | 화면 변화·목표 변경 시 3초 | 한 프레임의 UI 이동이 아닌 의미 변화 기준 3초±1초, 이전 안내 즉시 제거, 새 요청 이전 결과 무시 |
| V-05 | 목표 정정 · 통화 종료 · 권한 철회 | 양쪽 목표 갱신 5초 이내 목표. Hangup 뒤 안내 유지. 캡처 철회나 부모 끄기 뒤 표시 없음 |
| V-06 | 도착 추정 · 잘못된 완료 · 중복 명령 | 잘못된 도착에 완료 표시 없음. 지정 자녀의 완료만 최종 반영. 한 번 표시 뒤 상태 지움 |
| V-07 | 화면 수신 경로, 로그, 재시작 | 자녀 화면/RTC에 화면 영상 트랙 없음, 로그에 음성·프레임·주소 없음, 다음 도움에서 이전 이력 재사용 0건 |
