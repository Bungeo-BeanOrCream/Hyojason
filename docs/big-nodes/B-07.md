# B-07 · 역할별 상태 전달·완료·삭제

- **담당** D, A·B 협업
- **PRD 추적** C-14, D-4, E-3, F-1~F-5, G-1~G-3
- **하위 노드** [N-21](../small-nodes/N-21.md) · [N-22](../small-nodes/N-22.md) · [N-23](../small-nodes/N-23.md)
- **상태** 설계 계약 확정. 실제 환경 검증 전.

## 목적과 진입 조건

도움/역할 상태 갱신, 통화 후 도착 추정, 등록 자녀 완료, 부모 안내 끄기에서 실행한다. 부모 표시의 로컬 정리가 네트워크 응답을 기다리지 않는다.

## 입력 계약

| 타입 | 소유자 | 필요한 정보 |
|---|---|---|
| HelpSnapshot | B-04 | 목표·도움·통화·모드, 인증 대상 역할 |
| ArrivalDecision? | B-05 | 통화 후 확인된 arrival_id와 스코프 |
| EndCommand? | 각 인증 역할 | help_id, mode/goal revision, 완료 또는 중단 |

## 결과 계약

구간 결과는 `NodeResult<WorkflowData>`이며 `diagnostics.node_id=B-07`를 사용한다. 아래 데이터는 결과 경계에서 읽을 수 있는 필드다. 적용하지 않는 선택 출력은 null이며 지역 전용 값과 내부 진단을 역할 UI에 송신하지 않는다. 오류는 `outcome=null`, `data=null`이다. 하위 결과의 참조와 생략된 단계는 [공통 Diagnostic](../node-result-contract.md)에 남긴다.

| 필드 및 타입 | 값 또는 책임 |
|---|---|
| parent_view: ParentView? | 모드·현재 도움 상태·끄기 버튼·허용 목표 문구 |
| child_view: ChildView? | 최소 통화 상태·도움 완료·도착 추정 |
| end: EndEvent? | 양쪽 정리와 승인된 사유 |

## 호출 및 검증 정책

1. 상태 조회 → N-21. 자녀 UI 및 이벤트에는 목표·지시·관찰·진행 필드 제외.
2. POST_CALL_AGENT의 새 도착 추정 → N-22. 아직 완료가 아니며 arrival_id로 중복 제거.
3. 현재 도움에서 child complete 또는 parent stop → N-23. 이미 종료된 ID면 재정리해도 화면 효과는 0회.
4. 통화 중 완료 후 새 자녀 지시/목표와 유효 동의 → 새 help_id. 부모 중단이었다면 새로 동의할 때까지 대기.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| success | view_ready | 최신 인증 투영 성공 | 해당 역할 필드만 전달 |
| success | arrival_announced | 통화 후 최신 추정 또는 정당한 정정 | 알림 dedup, 도움 종료 없음 |
| success | help_closed | 명시적 자녀 완료 또는 부모 중단 | 현재 도움만 멱등 정리 |
| partial | cleanup_pending | 서버 종료 성공, 단말 응답 없음 | 다음 조회에서 old help 제거, 로컬 중단 안전 우선 |
| error | null | 역할·버전 불일치 | 알림 또는 종료 없음 |
