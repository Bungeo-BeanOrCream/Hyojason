# B-03 · 부모 화면 관찰과 전이 확정

- **담당** A, D 협업
- **PRD 추적** C-1~C-12, D-1, F-3, H-3
- **하위 노드** [N-07](../small-nodes/N-07.md) · [N-08](../small-nodes/N-08.md) · [N-09](../small-nodes/N-09.md) · [N-10](../small-nodes/N-10.md)
- **상태** 설계 계약 확정. 실제 환경 검증 전.

## 목적과 진입 조건

부모 앱에서 캡처 동의가 유효하고 foreground 서비스가 실행 중일 때 N-07에 연결한다. 새 기기 승인 또는 재승인에서 epoch를 새로 만들고, 활성 도움의 동일 epoch에서만 연속 프레임을 받는다.

## 입력 계약

| 타입 | 소유자 | 필요한 정보 |
|---|---|---|
| CaptureControl | B-04/N-07 | help_id, 시스템 승인 참조와 projection_epoch |
| RawFrame | MediaProjection | 로컬 frame_ref, rotation, viewport, captured_mono_ms |
| ScreenProfile | 검증 registry | app/profile_revision, 대상 단서와 보호 화면 힌트 |

## 결과 계약

구간 결과는 `NodeResult<WorkflowData>`이며 `diagnostics.node_id=B-03`를 사용한다. 아래 데이터는 결과 경계에서 읽을 수 있는 필드다. 적용하지 않는 선택 출력은 null이며 지역 전용 값과 내부 진단을 역할 UI에 송신하지 않는다. 오류는 `outcome=null`, `data=null`이다. 하위 결과의 참조와 생략된 단계는 [공통 Diagnostic](../node-result-contract.md)에 남긴다.

| 필드 및 타입 | 값 또는 책임 |
|---|---|
| screen: ScreenState? | server-safe 안정 화면과 의미 revision, target ID·근거 코드 |
| local: LocalObservation? | 부모 AVD 전용 layout_revision, 정확한 대상, 관측 시각 |
| capture_state: ACTIVE 또는 WAITING 또는 STOPPED | 상태 이벤트에 사용하는 값 |

## 호출 및 검증 정책

1. 새 시스템 승인 → N-07 epoch 발급; 캡처 정지·종료 → 원본·참조·공간 좌표 폐기.
2. N-08 usable → N-09, protected/invalid → 화면 요약으로 버튼·도착 추론 금지.
3. N-09 complete 또는 일부 독립적인 검증 단서 → N-10. 같은 의미 프레임 연속 2개에서 stable 기준.
4. 새 layout_revision → N-19 재매칭. 보호·공백 발생 → N-11 공백 기록과 부모 표시 제거.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| success | observed | 안정된 의미 화면 또는 로컬 위치 갱신 | 서버 전송 가능 요약 및 로컬 데이터를 분리 |
| success | waiting | 프레임 충분치 않거나 캡처 전 대기 | 안정화 대기, 화면 부재 추론 금지 |
| success | protected | 승인 범위 밖 보호 화면 | 비어 있는 제어 상태만 전송, 표시 즉시 제거 |
| partial | observation_gap | 일부 검출 실패 또는 전이 기록 누락 | N-12 경로 절단. 검증 단서만 범위 표시 |
| error | null | epoch 불일치 또는 필수 영상 처리 모두 실패 | 기존 위치 사용 금지, 재승인 또는 새 프레임 대기 |
