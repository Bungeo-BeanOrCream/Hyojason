# B-08 · AVD·GPU 운영·검증·시연

- **담당** D, C 모델 담당
- **PRD 추적** 시연과 성공 기준
- **하위 노드** [N-24](../small-nodes/N-24.md) · [N-25](../small-nodes/N-25.md) · [N-26](../small-nodes/N-26.md)
- **상태** 설계 계약 확정. 실제 환경 검증 전.

## 목적과 진입 조건

개발 환경 준비, 모델 revision이나 앱 버전 변경, 회귀·리허설에서 실행한다. N-24 환경과 N-26 GPU는 독립 준비한다. N-25는 확인할 수 있는 표본을 각각 판정한다.

## 입력 계약

| 타입 | 소유자 | 필요한 정보 |
|---|---|---|
| DeviceProfile[]와 FixtureRef[] | N-24 또는 개발 담당 | 두 Android AVD, 앱, 실제 UI 시연 자산 |
| DecisionCheck[]와 GPU 비용 | N-14/N-26 | 고정 revision, 실행 기록, 잔액과 $100 한도 |
| ScenarioCase[] 및 RunEvidence[] | N-24 및 B-01~07 | A/B, 지시/목표/위치/타이밍 테스트 로그 |

## 결과 계약

구간 결과는 `NodeResult<WorkflowData>`이며 `diagnostics.node_id=B-08`를 사용한다. 아래 데이터는 결과 경계에서 읽을 수 있는 필드다. 적용하지 않는 선택 출력은 null이며 지역 전용 값과 내부 진단을 역할 UI에 송신하지 않는다. 오류는 `outcome=null`, `data=null`이다. 하위 결과의 참조와 생략된 단계는 [공통 Diagnostic](../node-result-contract.md)에 남긴다.

| 필드 및 타입 | 값 또는 책임 |
|---|---|
| fixtures: FixturePrep? | 준비된 케이스와 재현 프로필 |
| runtime: RuntimeCheck? | 5종 실제 유형, GPU, 잔액 |
| evaluation: Evaluation? | 기대/실제, PASS/FAIL/UNVERIFIED, 지표별 분모 |

## 호출 및 검증 정책

1. N-24: APK/프로필·앱·언어 변경 때 다시 평가. 설정 A의 동일 화면 위치·오선택·스크롤 조건 반드시 준비.
2. N-26: L40S로 시작, GOAL/TARGET_LOCATION/ACTION_MATCH/NEXT_ACTION/ARRIVAL 실제 실행 확인. 과금 상한 기록.
3. N-25: 실제 A/B에서 B-01~07 trace를 연결하고 E01–E14는 합성으로 오류 경로 반복 재현. 모의와 실제 점수 합치지 않음.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| success | evaluation_recorded | 실행한 필수 실험의 증거와 수치 확인 | 실패 포함 보고. 기록 완료는 전 항목 통과와 별개 |
| partial | evidence_incomplete | 독립 표본 일부 차단 또는 측정 부족 | 누락 케이스 UNVERIFIED. 완주 수 증가 없음 |
| error | null | 기기·필수 모델 접근 전부 실패 또는 근거 포맷 불가 | 실제 시연 판정 중지 |
