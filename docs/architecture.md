# 전체 구조와 상태 전이

## 실행 환경

| 실행 위치 | 맡는 책임 | 상태의 소유자 |
|---|---|---|
| 부모님 Android AVD | 통화, 캡처 동의, 화면 처리, Overlay와 부모님 터치 | 원본 화면, 현재 로컬 창 좌표, 타이머, Overlay 표시 여부 |
| 자녀 Android AVD | 통화 수신, 최신 목표, 도착 추정 알림, 도움 완료 | 개인 권한과 UI 상태. 목표·도움 상태는 서버 확인값 표시 |
| LiveKit | 참가자의 실제 음성 교환 | 통화방과 오디오 트랙. 도움 완료의 저장소로 사용하지 않음 |
| 세션 및 Agent 서버 | 페어 권한, 도움 상태, 발화 처리 결과, Zoro-1 판단 및 역할별 이벤트 | 도움 ID, 확정 목표, 요약된 화면 상태, 방문 및 전이 힌트 |
| NVIDIA L40S | Zoro-1 실행 | 모델 revision과 실행 설정. 도움 데이터 영속 저장 없음 |

P0 기준은 Kotlin 기반 단일 Android APK, 역할을 분리한 ARM64 Android 15 AVD 두 대, 그리고 하나의 세션 서버 인스턴스다. 서버에서 LiveKit 토큰과 WebSocket 제어 채널을 제공한다. 백엔드 구현 제안은 Python과 FastAPI이며, 모델 endpoint와 제어 채널은 별도 장애로 다룬다. 두 역할 앱을 백그라운드 푸시로 깨우는 기능은 초기 시연 범위로 잡지 않고, 자녀 화면을 열어 둔 다음 앱 내 수신을 시험한다.

## 데이터 흐름

~~~text
부모 → 효자손에서 전화 요청 → 세션 서버가 승인된 자녀의 화면에 수신 표시
양측 수락·동의 → LiveKit 음성 연결 → 통화 중 양쪽 발화의 필요한 구간만 STT
                                         ↓
부모 AVD 캡처 → 로컬 화면 검출 → 정제한 ScreenState → 도움 상태 저장소
                                               ↘  확정 발화 + 현재 목표
                                           Zoro-1 System 1
                                                   ↓
부모 AVD: 유효한 안내 1개 + 로컬 3초·버전 검증    자녀 AVD: 목표/도착 추정/완료
      ↑                    ↓
현재 화면 재관찰 ← 부모님이 직접 버튼 누름·스크롤·입력
~~~

음성 스트림은 통화방으로 전달되고, 화면 영상은 LiveKit에 발행하지 않는다. STT가 필요한 구간만 동의한 참여자의 오디오 트랙으로 공급한다. 원본 오디오를 다른 사용자에게 돌려보내는 것 이외에 별도 저장·다운로드 경로를 두지 않는다. 부모님 화면은 단말에서 파싱한다. 모델에 전송하는 상태는 화면 분류, 등록된 버튼 라벨·ID, 동작 가능한 후보, 과업 완료 단서와 제한된 이력이다. 로컬 탐지 좌표와 실제 편지 내용은 부모 단말에 남긴다.

## 상태를 두 축으로 분리

| 축 | 상태 | 주요 전이 |
|---|---|---|
| 통화 | IDLE → RINGING → ACTIVE → ENDED | 수신 승인 후 연결. 거절·종료에 통화방과 음성 트랙 정리 |
| 도움 | IDLE → LISTENING → GUIDING → ARRIVAL_PENDING → ENDED | 연결된 통화와 양쪽 동의 후 수신. 확정 목표에서 GUIDING. 도착 추정만으로 종료하지 않음 |
| 관찰 | NOT_GRANTED → ACTIVE → GAP/STOPPED | 캡처 권한 취소·잠금·연결 공백 시 원 즉시 제거. 다시 승인 및 화면 확인 후에만 표시 재개 |

- 통화 종료 + 유효 목표 존재는 **통화 ENDED, 도움 GUIDING**이 될 수 있다. 새 발화 수집은 종료되고 마지막 확정 목표를 유지한다. 제어 채널이 살아 있어야 도착 알림과 완료 명령을 전달할 수 있다.
- 통화 종료 + 확정 목표 없음은 도움을 정리한다. 잠깐 접속이 끊긴 경우 SDK 상태와 FW 상태를 구별하여 음성 큐와 UI를 먼저 정리하고, 부모 관찰 재동의 요구 여부는 캡처 상태에 따라 판단한다.
- 도움 완료나 중단 + 통화 ACTIVE는 진행기록을 지우고 원과 캡처를 제거한다. 도움 완료 뒤 통화에 대한 안내 동의가 그대로 유효하면 STT는 관심 목표를 기다릴 수 있다. 새 목표는 새 도움으로 열고 화면 관찰을 재승인 받는다. 부모님이 안내를 끈 경우 같은 통화에서 부모님이 다시 안내를 켤 때까지 새 도움을 시작하지 않는다.
- AGENT 동의를 철회하면 안내와 STT를 멈춘다. 음성통화의 마이크 설정은 양쪽의 통화 조작으로 관리한다. 서버 재시작이 휘발성 도움 상태를 잃었으면 재개했다고 표시하지 않는다.
- 도착 추정 상태라도 변경된 화면이 도착 근거를 무효로 만들면 GUIDING 또는 화면 확인 대기로 돌아갈 수 있다. 완료는 자녀 명령만 유효하며 부모님 안내 끄기는 별개의 종료 사유다.

## 3초와 5초가 무엇을 재는가

부모 Android의 단조 증가 시계를 기준으로 목표 확정·변경 이벤트 또는 **의미 있는 화면 전이**마다 마감 시각을 3초 뒤로 설정한다. 이전 표시는 즉시 제거한다. 스크롤 또는 키보드 재배치로 좌표가 흔들리는 중에는 표시하지 않는다. 화면 종류가 안정화되기 전 선택은 따로 보류한다. 마감 시점에 선택과 위치가 유효할 때만 렌더한다. 늦게 도착한 선택은 같은 버전이고 최신 화면을 다시 확인할 수 있을 때만 뒤늦은 표시로 기록한다.

**목표 변경 5초**는 통화에서 정정이 끝난 시각부터 양쪽 화면이 새 목표를 표시할 때까지의 평가 목표다. 부모 화면의 첫 안내 3초와 별개로 재며, 자녀와 부모의 사용자 화면에 목표가 표시된 시각을 비교한다.

## 정정·이력 탐색

1. 화면이 실제로 바뀐 것을 보고 전이를 기록한다. 터치 신호를 직접 받은 것처럼 표현하지 않는다.
2. 새 확정 발화에서 Zoro-1이 변경 여부를 판단한다. “아니”만 들리면 정정 대상은 보류하되 기존 안내를 잠시 숨긴다.
3. 목표가 변하면 새 goal_revision을 배포하고 기존 행동을 폐기한다. 같은 앱에서 목표 옵션만 바뀌어도 revision을 갱신한다.
4. 최근 방문 노드 중 현재 위치와 관찰된 뒤로 가기 관계로 연결되는 후보를 찾는다. 전이가 실제 화면에서 검증됐을 때만 단거리 복귀 후보를 우선한다.
5. 다음 행동 하나를 Zoro-1이 고르고 부모가 조작한다. 관찰 결과를 확인한 뒤 다시 판단한다. 경로가 불명확하면 추가 조작을 추측하지 않는다.

기술 원칙과 상세 오류는 [공통 계약](contracts.md), 목표별 화면과 정정 가능한 위치는 [시나리오](scenarios.md)를 참고한다.
