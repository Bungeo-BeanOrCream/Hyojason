# N-26 · track_model_runtime_and_budget

- **위치와 담당** C · GPU·배포
- **상위 노드** [B-08](../big-nodes/B-08.md)
- **상태** 런타임·비용 판정과 N-25 증거 내보내기 구현. 실제 L40S 검증 필요.

Zoro 런타임 제공과 실제 총비용을 관리한다.

| 경계 | 계약 |
|---|---|
| 입력 | GPU SKU·단가·잔액, 가중치 revision과 engine, 요청 지연과 사용 기록 |
| 출력 | ModelReadiness(version, smoke_result, p95, spend), continue/hold |

## 처리 규칙

- L40S 한 대에서 호환과 실행이 확인된 경로를 사용한다. 모델/decision head 버전 변경은 별도 런타임 변경으로 기록한다.
- 설정 가능하면 타임아웃을 감안한 초기 시연 지연 상한을 정하고, 다섯 질문의 실제 호출의 표본과 지연을 기록한다.
- 워크플로 보통의 상태 변경과 안내 성공을 제어 서버에서 본다. 실험에 쓰는 GPU 시간, 부대비용과 종료 이후 과금을 확인하며 팀의 운영 한도에 맞춘다.

## 오류 및 보류

잔액 부족과 모델 접근 실패를 구분한다. 모의 선택을 실제 Zoro-1 호출 표시로 올리지 않는다.

## 구현 완료 기준

L40S에서 동일 revision 실제 모델 5종 요청이 성공하고 시작·중지, 시연 예비비와 대체 증거가 문서화됐다.

## 호출 조건과 책임 경계

- **호출 시점** L40S 준비·모델 revision 변경·예산 점검.
- **호출자 또는 입력 작성자** 모델 운영 담당과 실제 N-14 요청 기록.
- **책임 경계** 모델 준비 상태와 지출만 확인. 모의 경로를 실제로 표기하지 않음.

## 상세 입출력 계약

아래 필드는 노드별 입력과 `NodeResult.data`의 타입이다. 공통 반환과 버전·오류 필드는 [결과 계약](../node-result-contract.md)을 따른다. 표의 키는 모두 선언하고, null 허용 필드에 값이 없으면 null을 넣는다. `Local*` 및 `VolatileText` 값은 지정된 처리 경계에서만 쓰며 상태 투영, 재연결 응답, 진단 로그에 복사하지 않는다.

### 입력

| 필드 | 타입 | null 허용 |
|---|---|---|
| `model_revision` | `str` | 불가 |
| `gpu_sku` | `str` | 불가 |
| `spend_cents` | `int` | 불가 |
| `smoke_results` | `DecisionCheck[]` | 불가 |
| `credit_cents` | `int` | 불가 |

### 결과 데이터

| 필드 | 타입 | null 허용 |
|---|---|---|
| `model_ready` | `bool` | 불가 |
| `model_revision` | `str` | 불가 |
| `smoke_passes` | `int` | 불가 |
| `spend_cents` | `int` | 불가 |
| `budget_state` | `enum` | 불가 |

질문은 GOAL, TARGET_LOCATION, ACTION_MATCH, NEXT_ACTION, ARRIVAL이다. 금액은 센트 정수이며 credit_cents=10000을 사용한다. 누적 차감이 $70에 도달하면 새 실험을 보류하고, $100에 도달하면 예산 소진으로 표시한다. 운영자가 실제 중지를 확인한 값은 experiments_paused_at_70에 따로 받는다. GPU는 자원 효율이 검증된 SKU를 선택하되 첫 검증은 L40S로 계획한다.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `runtime_ready` | 5종 판단·동일 revision·예산 확인 | 실제 시연 도입 조건 충족 |
| `partial` | `budget_hold` | 모델은 확인됐지만 시연 예산에 여유 부족 | 추가 실험 멈춤, 잔액 재계산 |
| `error` | `null` | 실제 처리 실패·모델 접근/버전 오류 | 실제 시연으로 표시 금지 |

## 최소 검증과 기대 결과

| 케이스 | 입력 또는 재현 조건 | 기대 결과 |
|---|---|---|
| 26.1 | 5종 판단·동일 revision·예산 확인 | `success` / `runtime_ready`. 실제 시연 도입 조건 충족 |
| 26.2 | 모델은 확인됐지만 시연 예산에 여유 부족 | `partial` / `budget_hold`. 추가 실험 멈춤, 잔액 재계산 |
| 26.3 | 실제 처리 실패·모델 접근/버전 오류 | `error` / `null`. 실제 시연으로 표시 금지 |
| 26.4 | 경계 재현 · 확률 정상이나 revision 혼합 | `diagnostic.basis`가 호출의 입력 스코프와 일치한다. 동일 `run_id` 추적으로 위 반환 분류 및 구현 완료 기준을 확인한다. |

실행 모듈은 다섯 최초 요청을 N-14로 보내고, 선택 확인 여부·확률·지연·출처와 비용을 N-25의 V-08 JSON으로 내보낸다. 실행 예시는 [운영 안내](../../server/ops/README.md)에 있다.
