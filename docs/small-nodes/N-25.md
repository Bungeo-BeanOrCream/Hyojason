# N-25 · evaluate_end_to_end

- **위치와 담당** D · 리허설/통합, 전체 협업
- **상위 노드** [B-08](../big-nodes/B-08.md)
- **상태** [증거 평가 구현](../../server/session/hyojason_session/demo_evaluation.py) 및 FIXTURE 검증. 실제 A·B 각 5회와 모델·기기 증거는 [리허설 절차](../../demo/fixtures/README.md)에 따라 수집한다.

실제 라이브와 모의 시험을 분리하고 요구사항의 통과 여부를 기록한다.

| 경계 | 계약 |
|---|---|
| 입력 | PRD 성공 기준, 고정 20개 발화와 A·B 리허설, 표시·판단 로그 |
| 출력 | V-01~V-07 결과와 실패 보고서, 실제/모의 구분 |

## 처리 규칙

- 시나리오별 목표·작업 성공·정정·도착 알림·최종 완료를 각각 기록한다. 한 항목만 통과한 실행을 완주로 세지 않는다.
- 3초 이내 정답 0회 표시, 지시 17/20, 위치 85%, 목표 별도 집계, 예산과 모델 revision을 [실험 계획](../verification-plan.md)의 표본으로 측정한다. Zoro가 끊겼거나 시험 텍스트를 사용한 경로를 표시한다.
- 문제 화면 오류, 오래된 가이드, 가이드 터치, 네트워크 공백, 동의 철회를 검증한다. 테스트 계정 외의 오디오/화면 원본은 기록하지 않는다.

## 오류 및 보류

테스트 실패로 기능, 기기 또는 계약 중 어디가 확인되지 않았는지 구분한다. 보류와 오류를 성공으로 쓰지 않는다.

## 구현 완료 기준

A·B 각각 5회 및 20개 발화 결과표에 재현 순서와 기기·모델 버전이 남는다.

## 호출 조건과 책임 경계

- **호출 시점** 최소 시험과 라이브 리허설 수행.
- **호출자 또는 입력 작성자** N-24 프로필, 공통 추적 계약과 실제 이벤트 요약.
- **책임 경계** 판정을 실행 결과와 provenance로 분리. 품질을 근거 없이 승격하지 않음.

## 상세 입출력 계약

아래 필드는 노드별 입력과 `NodeResult.data`의 타입이다. 공통 반환과 버전·오류 필드는 [결과 계약](../node-result-contract.md)을 따른다. 표의 키는 모두 선언하고, null 허용 필드에 값이 없으면 null을 넣는다. `Local*` 및 `VolatileText` 값은 지정된 처리 경계에서만 쓰며 상태 투영, 재연결 응답, 진단 로그에 복사하지 않는다.

### 입력

| 필드 | 타입 | null 허용 |
|---|---|---|
| `scenarios` | `ScenarioCase[]` | 불가 |
| `observed_runs` | `RunEvidence[]` | 불가 |
| `criteria_revision` | `int` | 불가 |
| `expected_modes` | `enum[]` | 불가 |

### 결과 데이터

| 필드 | 타입 | null 허용 |
|---|---|---|
| `results` | `CaseResult[]` | 불가 |
| `counts` | `StatusCounts` | 불가 |
| `live_pass_count` | `int` | 불가 |
| `unverified_ids` | `str[]` | 불가 |

각 케이스는 expected와 actual을 따로 보존한다. 관측 시간 원점, 통화 전후 모드와 발화 종료→부모 수신을 구분한다. 관찰 증거가 누락된 경우 UNVERIFIED로 집계한다.

    completion -->|충족| accepted["검증된 결과와 근거 버전 반환"]
    completion -->|미충족| statusRule["아래 표에 따라 정상 빈 결과, 보류, 부분 또는 오류 반환"]

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `evaluation_recorded` | 필수 실측 및 모의 구분 완료 | 실패 결과도 그대로 보고 |
| `partial` | `evidence_incomplete` | 일부 측정이나 실제 기기 화면 증거 누락 | 검증 안 된 항목으로 별도 표기 |
| `error` | `null` | 기대값이나 근거 입력 전체가 없거나 형식 오류 | 통과율 계산 금지 |
