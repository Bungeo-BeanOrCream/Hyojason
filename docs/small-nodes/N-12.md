# N-12 · record_verified_navigation

- **위치와 담당** D · 제어 서버
- **상위 노드** [B-04](../big-nodes/B-04.md)
- **상태** 설계. 구현 및 시연 환경 검증 필요.

재안내 후보를 만들 수 있도록 실제로 관찰한 경로를 메모리에 남긴다.

| 경계 | 계약 |
|---|---|
| 입력 | screen.observed, 승인한 정규화 지시, 위치 및 수행 증거 |
| 출력 | NavigationTrail: 방문 화면, 확인 전이, revision, 관찰 공백 |

## 처리 규칙

- 최근 60개의 확인 기록을 보존한다. 검색은 최신 20개 전이까지 검사하고, 지시·위치·수행의 변경과 전이·공백을 구분해 적는다.
- 버튼 추론과 실제 관찰된 화면 변화를 구별한다. 빈 프레임/다른 앱 복귀를 정상 완료로 쓰지 않는다.
- 인증·전화번호·메일 내용·화면 원본·발화 원문은 기록하지 않는다. 종료/철회에서 제거한다.

## 오류 및 보류

공백을 지나온 화면은 연속 경로로 연결할 수 없다. 잘못된 앱 분류에서 새로운 BACK 경로가 만들어지지 않는다.

## 구현 완료 기준

디스플레이 조작 지시 뒤 다른 화면으로 가면 원래 화면과 검증된 전이 근거를 보존한다. 중간 캡처 공백이 있으면 두 화면을 잇지 않는다.

## 호출 조건과 책임 경계

- **호출 시점** 의미 화면 전이, 관찰 공백 또는 지시·위치·수행 결과가 검증·채택됨.
- **호출자 또는 입력 작성자** N-11 승인 이벤트·N-10 요약.
- **책임 경계** 확인된 지시 ID, 위치 근거, 화면 전이 및 수행 판정을 메모리에 유지. 원문·기하 좌표 제외.

## 상세 입출력 계약

아래 필드는 노드별 입력과 `NodeResult.data`의 타입이다. 공통 반환과 버전·오류 필드는 [결과 계약](../node-result-contract.md)을 따른다. 표의 키는 모두 선언하고, null 허용 필드에 값이 없으면 null을 넣는다. `Local*` 및 `VolatileText` 값은 지정된 처리 경계에서만 쓰며 상태 투영, 재연결 응답, 진단 로그에 복사하지 않는다.

### 입력

| 필드 | 타입 | null 허용 |
|---|---|---|
| `observed_transition` | `Transition` | 가능 |
| `directive_record` | `InstructionTrace` | 가능 |
| `help_id` | `str` | 불가 |
| `goal_revision` | `int` | 불가 |
| `trail` | `NavigationTrail` | 불가 |
| `observation_health` | `enum` | 불가 |

### 결과 데이터

| 필드 | 타입 | null 허용 |
|---|---|---|
| `trail` | `NavigationTrail` | 불가 |
| `trace_gap` | `bool` | 불가 |
| `recorded_edge` | `EdgeRef` | 가능 |
| `retained_count` | `int` | 불가 |

검증된 지시·위치·수행은 instruction_revision, target_id, evidence_codes, 원래/현재 화면 revision으로 남긴다. 위치는 이후 같은 버전에서 다시 로컬 확인한다. `NavigationTrail`은 동일 epoch의 연속 엣지, 공백 마커, 지시 채택과 위치 근거를 담는다. 원본과 좌표는 기록하지 않는다.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `edge_recorded` | 동일 epoch의 전후 화면이 관찰됨 | N-16에서 검증 복귀 또는 최단 경로 근거로 사용 가능 |
| `success` | `gap_recorded` | 캡처 공백이 정상 확인됨 | 공백을 가로지르는 경로 생성 금지 |
| `success` | `directive_recorded` | 지시·위치·수행 결과가 최신 토큰에서 채택됨 | 진행 이력에 근거 ID만 남김 |
| `success` | `unmodified` | 기록할 의미 화면 전이·지시 근거가 없음 | 이력을 변경하지 않음 |
| `error` | `null` | 다른 도움 또는 이전 epoch | 오류 자료를 탐색에 전달하지 않음 |

## 최소 검증과 기대 결과

| 케이스 | 입력 또는 재현 조건 | 기대 결과 |
|---|---|---|
| 12.1 | 동일 epoch의 전후 화면이 관찰됨 | `success` / `edge_recorded`. N-16에서 검증 복귀 또는 최단 경로 근거로 사용 가능 |
| 12.2 | 캡처 공백이 정상 확인됨 | `success` / `gap_recorded`. 공백을 가로지르는 경로 생성 금지 |
| 12.3 | 기록할 의미 화면 전이·지시 근거가 없음 | `success` / `unmodified`. 이력을 변경하지 않음 |
| 12.4 | 다른 도움 또는 이전 epoch | `error` / `null`. 오류 자료를 탐색에 전달하지 않음 |
| 12.5 | 현재 자녀 지시의 결정과 위치 확인 | `success/directive_recorded`. target_id/근거 코드만 남고 raw text/좌표 없음 |
| 12.6 | 경계 재현 · 앱 전환 중 캡처 공백 | `diagnostic.basis`가 호출의 입력 스코프와 일치한다. 동일 `run_id` 추적으로 위 반환 분류 및 구현 완료 기준을 확인한다. |
