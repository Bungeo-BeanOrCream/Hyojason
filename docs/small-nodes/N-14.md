# N-14 · infer_zoro_choice

- **위치와 담당** Agent 서버 · C
- **상위 노드** [B-05](../big-nodes/B-05.md)
- **상태** 계약 확정. 구현 및 실험 전.

다섯 종류 질문의 실제 Zoro-1 결과를 정형화한다.

## 호출 조건

N-15·27·28·17·18이 현재 허용 옵션을 모두 구성했을 때.

## 입출력 계약

다음 표는 노드 입력과 `NodeResult.data`의 필수 키다. [공통 결과와 Diagnostic](../node-result-contract.md)을 적용한다.

## 고정 워크플로우

~~~mermaid
flowchart TD
    start(["N-14 호출"]) --> valid{"모드, 권한, 관련 Basis가 유효한가?"}
    valid -->|유효| prepare["question_kind와 모드 조건 및 승인 옵션 검사"]
    valid -->|무효| rejected["오류 또는 소속된 정책 결과"]
    prepare --> decide["고정 모델 revision 호출 후 선택과 확률 검증"]
    decide --> checked{"typed response가 유효한가?"}
    checked -->|확인| result["검증된 결과와 실행 근거"]
    checked -->|미확인| wait["명시적 보류·부분·오류 결과"]
    rejected --> envelope(["NodeResult"])
    result --> envelope
    wait --> envelope
~~~

- GOAL, TARGET_LOCATION, ACTION_MATCH, NEXT_ACTION, ARRIVAL을 정의한다. GOAL은 확정 자녀 발화, TARGET_LOCATION/ACTION_MATCH는 CALL_CHILD_LED, NEXT_ACTION/ARRIVAL은 POST_CALL_AGENT에서만 호출한다.
- 질문 종류·스코프·관련 입력 버전·옵션 해시를 묶어 중복 호출을 막는다. 화면 틱마다 요청하지 않는다. 타임아웃은 low_confidence와 구분하고 새 유효 입력으로만 재평가한다.
- 옵션에 없는 ID, 모델 revision 불일치, 확률 NaN·범위 위반은 오류. 보류 여부는 N-15~18/27~28이 판단한다. LIVE/FIXTURE를 진단과 출력에 포함한다.

## 반환 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `inferred` | 현재 모드, 승인 선택지, 확률, 모델 revision 모두 유효 | 선택은 부수 효과가 없는 후보 값 |
| `error` | `null` | TIMEOUT, DEPENDENCY_UNAVAILABLE, 또는 불량 선택·확률 | 모의 판단을 실제로 대체하지 않는다. |
