# N-24 · prepare_demo_fixtures

- **위치와 담당** D · AVD/자료
- **상위 노드** [B-08](../big-nodes/B-08.md)
- **상태** 설계. 구현 및 시연 환경 검증 필요.

외부 네트워크와 기기 환경을 포함하여 5개 목표를 재현할 테스트 조건을 고정한다.

| 경계 | 계약 |
|---|---|
| 입력 | 두 AVD, 앱 버전, 역할·권한, 합성/테스트 자산 |
| 출력 | DemoFixtureList와 기기 상태, ready/blocked |

## 처리 규칙

- 동일 Android 버전과 한국어 UI를 맞추고 부모/자녀 앱 역할을 분리한다. 이어폰/스피커와 실제 마이크 경로를 확인한다.
- 설정값을 되돌릴 수 있도록 기록하고 Clock의 시간대·날짜, 지도 테스트 공개 장소, 메시지 상대 AVD 수신, Gmail 테스트 읽기 대상을 준비한다.
- 권한·로그인 화면은 본 시연 전 정리한다. 앱 버전, 화면 기준, 관찰 차단 여부를 시나리오별로 기록한다.

## 오류 및 보류

Android 제어 채널은 macOS 주소와 AVD 루프백을 구별한다. Gmail/지도 로그인이나 네트워크 실패를 앱 내부 성공으로 표기하지 않는다.

## 구현 완료 기준

새 에뮬레이터 환경에서 앱 열기부터 A·B의 최소 목표를 문서에 따라 재현.

## 호출 조건과 책임 경계

- **호출 시점** 개발 착수·리허설·AVD나 앱 버전 변경.
- **호출자 또는 입력 작성자** 통합 담당 입력 또는 점검 자동화.
- **책임 경계** 두 AVD와 앱별 최소 환경·예상 목표를 구성. 개인 계정·토큰을 산출물에 저장하지 않음.

## 상세 입출력 계약

아래 필드는 노드별 입력과 `NodeResult.data`의 타입이다. 공통 반환과 버전·오류 필드는 [결과 계약](../node-result-contract.md)을 따른다. 표의 키는 모두 선언하고, null 허용 필드에 값이 없으면 null을 넣는다. `Local*` 및 `VolatileText` 값은 지정된 처리 경계에서만 쓰며 상태 투영, 재연결 응답, 진단 로그에 복사하지 않는다.

### 입력

| 필드 | 타입 | null 허용 |
|---|---|---|
| `device_profiles` | `DeviceProfile[]` | 불가 |
| `fixture_revision` | `int` | 불가 |
| `scenario_ids` | `str[]` | 불가 |
| `staged_assets` | `FixtureRef[]` | 불가 |

### 결과 데이터

| 필드 | 타입 | null 허용 |
|---|---|---|
| `fixture_revision` | `int` | 불가 |
| `ready_scenarios` | `str[]` | 불가 |
| `blocked_scenarios` | `BlockReason[]` | 불가 |

fixture_revision과 device profile을 묶어 준비 완료를 판단한다. A는 재현 가능한 빠른 정답·잘못된 이동·아래쪽 대상·현재 대상, B는 자녀 첫 지시·유효 알람·RTC 종료 뒤 화면 경로를 준비한다. 합성 데이터와 시연 자산을 문서 증거에서 식별한다.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `fixtures_ready` | 요구 앱과 두 역할 접근 조건 확인 | 리허설 진행, 실제 버전 기록 |
| `partial` | `some_fixtures_blocked` | 독립된 일부 시나리오만 준비 | 통과 시나리오만 시작, 전체 완료 주장 금지 |
| `error` | `null` | 필수 두 역할이나 AVD 프로필 모두 준비되지 않음 | 정상 시연 시작 불가 |
