# N-11 · reduce_help_state

- **위치와 담당** D · 제어 서버
- **상위 노드** [B-04](../big-nodes/B-04.md)
- **상태** [서버 상태 처리 구현](../../server/session/help_state.py). [FIXTURE 단위 테스트](../../tests/test_help_state.py)는 인증된 역할과 상위 노드의 이벤트를 주입한다. 두 AVD를 사용한 실통화 검증은 후속 통합에서 진행한다.

통화/도움/관찰과 목표 revision을 단일 처리 경로로 갱신한다.

| 경계 | 계약 |
|---|---|
| 입력 | 인증된 call/consent/screen/utterance/goal/arrival/complete 이벤트 |
| 출력 | HelpSnapshot, state effects, duplicate / stale / rejected |

## 처리 규칙

- 인증 이벤트를 도움별로 직렬화한다. 최신 자녀 발화의 지시와 명시 목표를 별도 채택한다. 이전 목표가 있다고 변경 판단을 호출하지 않는다.
- 새 자녀 지시에서 instruction_revision을 증가시키고 부모에게 instruction.accepted를 한 번 발행한다. 첫 유효 자녀 지시 또는 목표는 call_id에 묶어 N-03 오디오 경로 변경 평가를 한 번 발행한다.
- 확정 hangup에서 STT를 닫고 기존 지시·타이머를 취소한다. 유효 목표가 있으면 같은 help_id에서 POST_CALL_AGENT 및 mode_revision을 발행하고 부모 재관찰을 요청한다. RTC 일시 순단은 후속 모드를 열지 않는다.
- 새 지시·목표가 기존 완료 세션을 다시 쓰지 않는다. 부모 중단 기준이 적용되는 경우 부모 재동의가 먼저다.

## 구현 완료 기준

새 자녀 지시 뒤 늦게 온 이전 위치, hangup 뒤 통화 중 결과, 종료된 도움의 완료를 입력한다. 세 경우 모두 최신 세션에 가이드·상태 변화를 일으키지 않는다.

## 호출 조건과 책임 경계

- **호출 시점** 제어 이벤트의 직렬 적용.
- **호출자 또는 입력 작성자** 인증된 입력 큐 및 N-06/N-10/N-15/N-22 결과.
- **책임 경계** 통화, 모드, 지시, 목표, 관찰 상태의 권위 버전 작성.

## 상세 입출력 계약

아래 필드는 노드별 입력과 `NodeResult.data`의 타입이다. 공통 반환과 버전·오류 필드는 [결과 계약](../node-result-contract.md)을 따른다. 표의 키는 모두 선언하고, null 허용 필드에 값이 없으면 null을 넣는다. `Local*` 및 `VolatileText` 값은 지정된 처리 경계에서만 쓰며 상태 투영, 재연결 응답, 진단 로그에 복사하지 않는다.

### 입력

| 필드 | 타입 | null 허용 |
|---|---|---|
| `event` | `Event` | 불가 |
| `previous_state` | `HelpSnapshot` | 가능 |
| `basis` | `Basis` | 불가 |
| `actor_role` | `enum` | 불가 |

### 결과 데이터

| 필드 | 타입 | null 허용 |
|---|---|---|
| `snapshot` | `HelpSnapshot` | 불가 |
| `side_effects` | `EffectRef[]` | 불가 |
| `applied_event_seq` | `int` | 불가 |

한 세션에서 이벤트를 순서대로 단일 작성한다. 비동기 결과 적용 가드는 처리 중 seq와 현재 seq가 같을 것을 요구하지 않으며, 소유 스코프 버전을 비교한다.

    check -->|거부| reject["처리 중단 또는 정책 결과를 기록"]
    first --> second["이벤트 1회 적용 및 부수효과 등록"]
    second --> completion{"현재 버전에 적용 가능한가?"}
    completion -->|충족| accepted["검증된 결과와 근거 버전 반환"]
    completion -->|미충족| statusRule["아래 표에 따라 정상 빈 결과, 보류, 부분 또는 오류 반환"]
    reject --> result(["NodeResult"])

    statusRule --> result
~~~

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `state_applied` | 정상 사건이 현재 상태에 반영 | snapshot으로 다음 호출 결정 |
| `success` | `duplicate_ignored` | 동일 event_id가 이미 적용됨 | 새 상태·외부 출력 없음 |
| `success` | `call_ended_help_active` | 확정 목표가 있을 때 통화 종료 | STT와 통화 지시 종료. 도움·캡처 유지, post-call 모드 전환 |
| `error` | `null` | 역할 위조·이전 도움/목표에 대한 변경 | 현재 최신 상태 유지 |

## 최소 검증과 기대 결과

| 케이스 | 입력 또는 재현 조건 | 기대 결과 |
|---|---|---|
| 11.1 | 정상 사건이 현재 상태에 반영 | `success` / `state_applied`. snapshot으로 다음 호출 결정 |
| 11.2 | 동일 event_id가 이미 적용됨 | `success` / `duplicate_ignored`. 새 상태·외부 출력 없음 |
| 11.3 | 확정 목표가 있을 때 통화 종료 | `success` / `call_ended_help_active`. STT와 통화 지시 종료. 도움·캡처 유지, post-call 모드 전환 |
