# N-10 · confirm_screen_transition

- **위치와 담당** A · Android
- **상위 노드** [B-03](../big-nodes/B-03.md)
- **상태** 설계. 구현 및 시연 환경 검증 필요.

실제 화면의 의미 변화와 레이아웃 변경을 분리하고 안정된 상태만 발행한다.

| 경계 | 계약 |
|---|---|
| 입력 | 연속 LocalObservation, 최근 화면·layout, pending 타이머 |
| 출력 | screen.observed와 screen_revision, location_invalidated, observation_gap |

## 처리 규칙

- 이전 화면과 다른 안정된 키·컨트롤 집합을 비교한다. 전이 가능성이 있는 순간 원을 먼저 숨기고 같은 새 화면 2회 확인 후 새 revision을 발행한다.
- 스크롤, 키보드, 글자 크기 배치에서는 layout을 먼저 갱신한다. 화면 의미까지 바뀌면 새 단계로 올린다.
- 전이는 관찰된 두 화면과 근거를 제공한다. 사용자의 실제 터치 좌표·발생 여부를 확정하지 않는다.

## 오류 및 보류

프레임 끊김이나 보호 화면은 현재 상태를 unknown으로 표시하고 대시보드에는 gap만 넘긴다.

## 구현 완료 기준

통화 중 화면 전이는 지시의 타이머를 재시작하지 않는다. 다른 Settings 화면이 관측되면 이전 표시를 제거하고 화면 revision을 증가시킨다. 통화 후에만 안정된 의미 전이로 N-19의 타이머가 시작된다.

## 호출 조건과 책임 경계

- **호출 시점** 화면 판별 또는 로컬 관찰 공백이 도착.
- **호출자 또는 입력 작성자** N-09 결과와 현재 안정된 로컬 관찰.
- **책임 경계** 의미 변화, 레이아웃 변경, 관찰 공백을 구분하고 현재 화면만 커밋.

## 상세 입출력 계약

아래 필드는 노드별 입력과 `NodeResult.data`의 타입이다. 공통 반환과 버전·오류 필드는 [결과 계약](../node-result-contract.md)을 따른다. 표의 키는 모두 선언하고, null 허용 필드에 값이 없으면 null을 넣는다. `Local*` 및 `VolatileText` 값은 지정된 처리 경계에서만 쓰며 상태 투영, 재연결 응답, 진단 로그에 복사하지 않는다.

### 입력

| 필드 | 타입 | null 허용 |
|---|---|---|
| `observation` | `LocalObservation` | 불가 |
| `baseline` | `LocalObservation` | 가능 |
| `previous_screen_revision` | `int` | 불가 |
| `projection_epoch` | `str` | 불가 |

### 결과 데이터

| 필드 | 타입 | null 허용 |
|---|---|---|
| `screen_kind` | `enum` | 불가 |
| `screen_revision` | `int` | 불가 |
| `layout_revision` | `int` | 불가 |
| `target_ids` | `str[]` | 불가 |
| `verified_signals` | `enum[]` | 불가 |
| `observation_health` | `enum` | 불가 |

확정 전이라도 화면 행동 단서가 보이면 부모 게이트에 판정 대기 신호를 전달한다. screen_revision은 의미가 바뀔 때만 증가한다. 좌표만 변경되면 layout_revision으로 기존 표시를 무효화한다.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `screen_changed` | 다른 의미 화면이 연속 확인됨 | 기존 표시 제거, 새 screen.observed 발행 |
| `success` | `layout_changed` | 같은 화면에서 좌표·IME 이동 | 위치 재검증, 의미 전이로 처리하지 않음 |
| `success` | `observation_gap` | 현 상태를 확인하지 못하는 구간 시작 | 숨김, 이력 연속으로 이어 붙이지 않음 |
| `error` | `null` | 이전 캡처 epoch 또는 불일치 | STALE_BASIS, 현재 상태 오염 금지 |

## 최소 검증과 기대 결과

| 케이스 | 입력 또는 재현 조건 | 기대 결과 |
|---|---|---|
| 10.1 | 다른 의미 화면이 연속 확인됨 | `success` / `screen_changed`. 기존 표시 제거, 새 screen.observed 발행 |
| 10.2 | 같은 화면에서 좌표·IME 이동 | `success` / `layout_changed`. 위치 재검증, 의미 전이로 처리하지 않음 |
| 10.3 | 현 상태를 확인하지 못하는 구간 시작 | `success` / `observation_gap`. 숨김, 이력 연속으로 이어 붙이지 않음 |
