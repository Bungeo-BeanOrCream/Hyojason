# N-15 · interpret_child_turn

- **위치와 담당** Agent 서버 · C
- **상위 노드** [B-05](../big-nodes/B-05.md)
- **상태** 계약 확정. 구현 및 실험 전.

확정 자녀 발화에서 버튼 지시와 명시적 목표를 분리한다.

## 호출 조건

현재 통화의 최신 speech.final이 자녀 트랙에 속할 때.

## 입출력 계약

다음 표는 노드 입력과 `NodeResult.data`의 필수 키다. [공통 결과와 Diagnostic](../node-result-contract.md)을 적용한다.

### 입력

| 필드 | 타입 | null |
|---|---|---|
| `speech` | `FinalUtterance` | 불가 |
| `existing_goal` | `Goal` | 허용 |
| `goal_catalog_revision` | `int` | 불가 |
| `basis` | `Basis` | 불가 |

### 결과 데이터

| 필드 | 타입 | null |
|---|---|---|
| `instruction_draft` | `InstructionDraft` | 허용 |
| `goal_draft` | `GoalDraft` | 허용 |
| `turn_kind` | `enum` | 불가 |
| `confidence` | `number` | 허용 |
| `supersedes_previous` | `bool` | 불가 |

## 고정 워크플로우

~~~mermaid
flowchart TD
    start(["N-15 호출"]) --> valid{"모드, 권한, 관련 Basis가 유효한가?"}
    valid -->|유효| prepare["P0 단일 행동과 승인 라벨 단서 정규화"]
    valid -->|무효| rejected["오류 또는 소속된 정책 결과"]
    prepare -->|지시 초안 확인| acceptDraft["B-05가 지시 초안을 N-11에 먼저 전달"]
    prepare --> decide["명시 목표 단서가 있으면 N-14 GOAL과 필수 슬롯 점검"]
    decide --> checked{"지시 또는 유효 목표가 있는가?"}
    checked -->|확인| result["검증된 결과와 실행 근거"]
    checked -->|미확인| wait["명시적 보류·부분·오류 결과"]
    rejected --> envelope(["NodeResult"])
    acceptDraft --> envelope
    result --> envelope
    wait --> envelope
~~~

- 지시 초안과 목표 초안은 B-05가 N-11에 별도 전송한다. 유효 지시 초안은 목표 모델 응답을 기다리지 않는다. 최종 결과는 진단용이며 이미 전달한 초안을 반복 적용하지 않는다.
- 짧은 버튼 지시는 한 행동·라벨 하나를 잠정 표현한다. 등록된 동의어나 ‘그 버튼’처럼 모호한 라벨은 N-27에서 화면 옵션 또는 UNKNOWN에 매핑한다.
- 목표 변경 분류 질문은 없다. 기존 목표가 있더라도 실제 명시한 지원 목표 기준으로 GOAL을 산출해 N-11에 전달하고 동일 목표·슬롯은 revision을 늘리지 않는다.
- 분명한 새 버튼 지시이면 새 revision으로 이전 것을 종료한다. 지시 아닌 말, 부모 발화, 중간 전사는 기존 지시를 변경하지 않는다. 여러 단계를 자동으로 큐잉하지 않는다.

## 반환 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `instruction_ready` | 한 개 자녀 행동 인식, 목표 여부는 독립 | N-11 지시 채택 및 필요 시 목표 업데이트 |
| `success` | `goal_only` | 명시 목표와 유효 슬롯, 버튼 지시 없음 | 목표만 저장, 통화 중 표시 예약 없음 |
| `success` | `waiting` | 모호·목표 없음·잡담, 지시의 필요 조건 미충족 | 대기. 새 지시임이 확실할 때만 이전 표시 무효화 |
| `success` | `policy_denied` | 지시가 금지 위험 범위 | 조작 지시 폐기, 보호 문구만 |
| `partial` | `instruction_only` | 유효 지시는 있으나 별도의 목표 추론/필수 슬롯 실패 | 지시만 써서 개입 가능, 실패한 목표로 인계 금지 |
| `error` | `null` | 이전 자녀 utterance_seq 또는 처리 필수 단계 실패 | 검증된 초안이 전혀 없는 경우에만 error. 별개 지시가 검증됐으면 partial |
