# N-01 · resolve_pair

- **위치와 담당** B · 세션 서버/Android 온보딩
- **상위 노드** [B-01](../big-nodes/B-01.md)
- **상태** 설계. 구현 및 시연 환경 검증 필요.

승인된 부모와 자녀 한 명으로 페어를 제한하고 화면에 표시할 관계만 반환한다.

| 경계 | 계약 |
|---|---|
| 입력 | 인증 단말 ID, 역할, 등록 코드 또는 승인된 페어 ID |
| 출력 | PairView(pair_id, role, peer_alias, peer_available), paired / pending / declined |

## 처리 규칙

- P0 온보딩은 권한 안내→일회용 가족 연결→동의 확인을 한 화면에서 하나씩 보여준다.
- 코드는 서버가 만료·일회용으로 관리한다. 부모/자녀 역할을 인증 정보에서 결정하고 페어 확정은 양쪽 승인 이후에만 한다.
- 부모 홈에는 지정된 자녀 사진과 발신 1개를 노출한다. 앱은 원격 이메일/연락처를 가져오지 않고 테스트 사진을 쓸 수 있다.

## 오류 및 보류

만료·이미 사용한 코드, 제3자 요청, 중복 페어는 권한 오류. 잘못된 인증은 상대 존재 여부를 드러내지 않는다.

## 구현 완료 기준

부모 P, 자녀 C는 연결되고 제3 단말 X로 같은 코드 재사용 시 등록되지 않는다.

## 호출 조건과 책임 경계

- **호출 시점** 첫 페어 등록 또는 부모 홈 진입.
- **호출자 또는 입력 작성자** 제어 서버의 인증된 등록·조회 요청.
- **책임 경계** 인증된 부모·자녀 관계만 제공. RTC 토큰 발급은 N-03.

## 상세 입출력 계약

아래 필드는 노드별 입력과 `NodeResult.data`의 타입이다. 공통 반환과 버전·오류 필드는 [결과 계약](../node-result-contract.md)을 따른다. 표의 키는 모두 선언하고, null 허용 필드에 값이 없으면 null을 넣는다. `Local*` 및 `VolatileText` 값은 지정된 처리 경계에서만 쓰며 상태 투영, 재연결 응답, 진단 로그에 복사하지 않는다.

### 입력

| 필드 | 타입 | null 허용 |
|---|---|---|
| `actor_id` | `str` | 불가 |
| `role` | `enum` | 불가 |
| `invite_code` | `str` | 가능 |
| `pair_id` | `str` | 가능 |

### 결과 데이터

| 필드 | 타입 | null 허용 |
|---|---|---|
| `pair_id` | `str` | 가능 |
| `role` | `enum` | 불가 |
| `peer_alias` | `str` | 가능 |
| `peer_available` | `bool` | 불가 |
| `approval_state` | `enum` | 불가 |

페어 조회에서 actor_id는 세션 인증 결과로 결정한다. 초대 코드는 한 번 승인되면 재사용할 수 없다.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `paired` | 양쪽 승인과 역할 일치 | 활성 페어만 N-02/N-03에 전달 |
| `success` | `pending` | 상대 승인이 아직 없음 | 방 생성 금지, 다음 승인 이벤트 대기 |
| `error` | `null` | 코드 만료·재사용 또는 제3자 | UNAUTHORIZED, 다른 페어 정보 노출 금지 |

## 최소 검증과 기대 결과

| 케이스 | 입력 또는 재현 조건 | 기대 결과 |
|---|---|---|
| 01.1 | 양쪽 승인과 역할 일치 | `success` / `paired`. 활성 페어만 N-02/N-03에 전달 |
| 01.2 | 상대 승인이 아직 없음 | `success` / `pending`. 방 생성 금지, 다음 승인 이벤트 대기 |
| 01.3 | 코드 만료·재사용 또는 제3자 | `error` / `null`. UNAUTHORIZED, 다른 페어 정보 노출 금지 |
| 01.4 | 경계 재현 · 가족이 앱에서 승인 | `diagnostic.basis`가 호출의 입력 스코프와 일치한다. 동일 `run_id` 추적으로 위 반환 분류 및 구현 완료 기준을 확인한다. |
