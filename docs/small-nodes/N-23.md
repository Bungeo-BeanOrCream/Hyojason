# N-23 · purge_help_and_restart

- **위치와 담당** D · 서버, A·B 클라이언트
- **상위 노드** [B-07](../big-nodes/B-07.md)
- **상태** 설계. 구현 및 시연 환경 검증 필요.

끝난 도움의 관찰과 데이터를 지우고 새 도움은 빈 상태에서 연다.

| 경계 | 계약 |
|---|---|
| 입력 | HelpEndRequested, 통화·권한 상태, 클라이언트·서버 대기열 |
| 출력 | help.ended(reason), 각 역할 정리 상태, 다음 도움 수신 가능 여부 |

## 처리 규칙

- 서버에서 도움 이력·목표·추론 후보·대기 발화를 비우고 늦은 응답을 무시할 상태를 만든다. 식별자와 종료 사유에 필요한 최소 상태만 남긴다.
- 부모에서 캡처·좌표·타이머·원과 상단 띠를 없앤다. 자녀 완료 버튼을 비우고 도착 알림을 내린다.
- 자녀가 완료했고 통화 동의가 여전히 유효하면 새 발화를 기다린다. 부모님 중단의 경우 부모님이 다시 안내를 켤 때까지 새 도움을 열지 않는다. 새 자녀 지시 또는 목표에는 새 help_id와 필요한 캡처 승인을 사용한다.

## 오류 및 보류

네트워크 오류가 있으면 부모 끄기는 로컬에서 즉시 정리, 자녀 상태는 재접속으로 갱신. 비활성 30분 정리는 P1.

## 구현 완료 기준

도움을 마친 뒤 기존 녹음/프레임 또는 목표가 남지 않고 같은 통화의 새 자녀 지시 또는 목표가 전혀 다른 도움으로 생성된다.

## 호출 조건과 책임 경계

- **호출 시점** 승인된 종료 또는 부모 로컬 즉시 정리.
- **호출자 또는 입력 작성자** N-22의 종료 승인, 사용자·OS 중단 신호.
- **책임 경계** 실행 흔적과 민감한 맥락의 수명을 종료. 새 도움은 빈 상태.

## 상세 입출력 계약

아래 필드는 노드별 입력과 `NodeResult.data`의 타입이다. 공통 반환과 버전·오류 필드는 [결과 계약](../node-result-contract.md)을 따른다. 표의 키는 모두 선언하고, null 허용 필드에 값이 없으면 null을 넣는다. `Local*` 및 `VolatileText` 값은 지정된 처리 경계에서만 쓰며 상태 투영, 재연결 응답, 진단 로그에 복사하지 않는다.

### 입력

| 필드 | 타입 | null 허용 |
|---|---|---|
| `help_id` | `str` | 불가 |
| `end_reason` | `enum` | 불가 |
| `rtc_active` | `bool` | 불가 |
| `role` | `enum` | 불가 |
| `consent_active` | `bool` | 불가 |

### 결과 데이터

| 필드 | 타입 | null 허용 |
|---|---|---|
| `end_event_id` | `str` | 불가 |
| `end_reason` | `enum` | 불가 |
| `cleared_scopes` | `enum[]` | 불가 |
| `resume_requires_consent` | `bool` | 불가 |

clear 연산은 help_id 단위로 멱등 처리한다. 통화가 살아 있고 완료 뒤 동의가 남았으면 새 자녀 지시·목표는 새 도움 ID를 연다. 부모 중단이면 부모가 재활성 동의할 때까지 기다린다. RTC 연결이 남아 있다면 동의 철회 이후에는 음성 통화 상태만 남긴다.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `help_ended` | 현재 도움의 승인된 종료와 정리 | 상태·결과·프레임·핑 큐 정리 |
| `success` | `already_ended` | 같은 도움을 두 번 종료 | 중복 부수 효과 없음 |
| `partial` | `local_cleanup_pending` | 서버는 종료했으나 단말 연결이 끊겨 정리 확인 없음 | 단말 재접속 시 최신 상태로 정리, 동시 실행 금지 |
| `error` | `null` | 이전/다른 도움을 대상으로 요청 | 현재 도움 데이터는 유지 |
