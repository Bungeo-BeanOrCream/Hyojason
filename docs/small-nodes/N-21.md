# N-21 · project_role_view

- **위치와 담당** D · 서버, B 자녀 UI
- **상위 노드** [B-07](../big-nodes/B-07.md)
- **상태** [역할별 투영 구현](../../server/session/hyojason_session/role_view.py). [FIXTURE 단위 테스트](../../server/session/tests/test_n21_project_role_view.py)에서 21.1~21.4를 재현한다. 투영 필드는 [계약 추가 제안](../work/D-role-view-contract.md)의 초안이며, 상태 변경 때의 역할별 전송과 실제 앱 화면 확인은 후속 통합에서 진행한다.

부모·자녀 화면에 각각 허용된 상태를 전달한다.

| 경계 | 계약 |
|---|---|
| 입력 | HelpSnapshot, actor_role, 최신 goal 및 arrival 결과 |
| 출력 | ParentView 또는 ChildView(call_state, can_complete, arrival_indicator) |

## 처리 규칙

- ParentView는 통화/도움 모드, 검증된 현재 목표와 안내 끄기, 완료 문구를 제공한다.
- ChildView의 허용 키는 call_state, can_complete, arrival_indicator로 한정한다. AI가 인식한 지시, 목표·단계 진행, 이력·좌표·화면을 자녀 앱에 전송하지 않는다. 도움 상태는 완료 버튼의 가능 여부로만 사용한다.
- 재연결에서도 같은 필드 권한을 적용한다. 원본 서버 상태와 부모 유효 안내 명령은 RoleSnapshot에 그대로 싣지 않는다.

## 구현 완료 기준

같은 도움을 양쪽에서 조회한다. 목표·상태는 부모만 받으며, 자녀의 완료는 가능한 동안 활성이고 도착 추정은 통화 후에만 나타난다.

## 호출 조건과 책임 경계

- **호출 시점** 목표·통화·도움 상태가 바뀌거나 앱이 다시 연결.
- **호출자 또는 입력 작성자** N-11/N-13 최신 권위 snapshot, N-22의 알림 상태.
- **책임 경계** 각 역할에 허용된 화면 데이터만 조립.

## 상세 입출력 계약

아래 필드는 노드별 입력과 `NodeResult.data`의 타입이다. 공통 반환과 버전·오류 필드는 [결과 계약](../node-result-contract.md)을 따른다. 표의 키는 모두 선언하고, null 허용 필드에 값이 없으면 null을 넣는다. `Local*` 및 `VolatileText` 값은 지정된 처리 경계에서만 쓰며 상태 투영, 재연결 응답, 진단 로그에 복사하지 않는다.

### 입력

| 필드 | 타입 | null 허용 |
|---|---|---|
| `snapshot` | `HelpSnapshot` | 불가 |
| `viewer_role` | `enum` | 불가 |
| `arrival_state` | `enum` | 불가 |
| `online` | `bool` | 불가 |

### 결과 데이터

| 필드 | 타입 | null 허용 |
|---|---|---|
| `role` | `enum` | 불가 |
| `parent_view` | `ParentView` | 가능 |
| `child_view` | `ChildView` | 가능 |

조회 시점 역할을 기준으로 필드를 선택한다. 해당 역할의 view만 채우고 다른 역할 view는 null. 실제 전송은 해당 투영만 사용한다.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `view_ready` | 페어 역할에 맞게 현재 상태 조립 | 자녀는 통화 UI·도착·완료 제어만 수신 |
| `success` | `view_waiting` | 활성 통화 중 아직 지시나 목표 없음 | 부모에 듣는 상태, 자녀에는 기존 통화 UI |
| `error` | `null` | 타 페어 또는 이전 도움의 snapshot | 화면·목표 데이터 제공 금지 |
