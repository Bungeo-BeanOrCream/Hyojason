# N-03 · start_or_close_call

- **위치와 담당** B · Android/RTC/서버
- **상위 노드** [B-01](../big-nodes/B-01.md)
- **상태** 설계. 구현 및 시연 환경 검증 필요.

발신·수신(부모·자녀 누구나 발신, 상대가 수락)과 RTC 연결, 오디오 출력, RTC 종료 흐름만 관리한다.

| 경계 | 계약 |
|---|---|
| 입력 | 승인된 페어, 발신/수락/끊기, RTC room 참가·연결, 오디오 장치 |
| 출력 | CallState와 call_id, 양쪽 역할의 연결 여부, 종료 사유 |

## 처리 규칙

- 발신→상대 화면 초대→상대 수락 후 역할별 단기 RTC 토큰→두 사람의 트랙 확인. P0 수신 화면은 개발 앱이 열려 있다고 가정한다.
- 가시 Activity에서 녹음 권한 및 배경 통화에 필요한 서비스 유형을 준비한다. 화면만 전환해도 연결이 유지되는지 검증한다.
- 오디오 출력은 RTC 연결 시 역할별로 한 번 정한다. 부모는 스피커폰(설정 화면을 보며 듣기), 자녀는 수화기. 이어폰이나 Bluetooth가 연결돼 있으면 그 경로를 유지한다. 앱에 음소거 버튼은 두지 않는다(일반 전화처럼).
- 종료는 RTC만 연결 해제하고 call.ended를 보낸다. 제어 채널·도움 완료는 별도의 상태머신에 맡긴다.

## 오류 및 보류

재수락은 새 방을 만들지 않음. 오디오 차단, 수신 타임아웃, 참가 실패를 구별하고 로컬 세션을 복구한다.

## 구현 완료 기준

양쪽 AVD가 교대로 말하며 부모가 Settings 전환, 자녀 끊기 뒤 부모는 다른 앱을 계속 쓰는지 확인.

## 호출 조건과 책임 경계

- **호출 시점** 발신·상대 수락·RTC 연결/종료 이벤트, 첫 자녀 지시/목표.
- **호출자 또는 입력 작성자** 양쪽 역할 UI와 LiveKit 콜백, N-01/N-02.
- **책임 경계** 오디오 연결과 오디오 라우팅만 담당. 도움의 종료는 N-11/N-22.

## 상세 입출력 계약

아래 필드는 노드별 입력과 `NodeResult.data`의 타입이다. 공통 반환과 버전·오류 필드는 [결과 계약](../node-result-contract.md)을 따른다. 표의 키는 모두 선언하고, null 허용 필드에 값이 없으면 null을 넣는다. `Local*` 및 `VolatileText` 값은 지정된 처리 경계에서만 쓰며 상태 투영, 재연결 응답, 진단 로그에 복사하지 않는다.

### 입력

| 필드 | 타입 | null 허용 |
|---|---|---|
| `pair_id` | `str` | 불가 |
| `call_id` | `str` | 가능 |
| `operation` | `enum` | 불가 |
| `actor_role` | `enum` | 불가 |
| `room_state` | `enum` | 불가 |
| `headset_connected` | `bool` | 불가 |
| `first_child_intent_event_id` | `str` | 가능 |

### 결과 데이터

| 필드 | 타입 | null 허용 |
|---|---|---|
| `call_id` | `str` | 불가 |
| `call_state` | `enum` | 불가 |
| `connected_roles` | `enum[]` | 불가 |
| `audio_route` | `enum` | 불가 |
| `end_reason` | `enum` | 가능 |

RTC 미디어 연결 상태와 도움 상태는 별도다. call_id는 새 통화마다 만들고 토큰은 현재 페어와 역할에 한정한다.

## 결과 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `active` | 두 역할 실제 RTC 연결 완료 | 통화 상태 갱신, 동의 시 B-02 시작 |
| `success` | `ended` | 사용자가 통화만 종료 | RTC와 STT 정리, 도움 지속 여부는 N-11 판단 |
| `partial` | `route_fallback` | 두 역할 연결 성공, 스피커 전환 실패 | 시스템 오디오 경로 유지, 실패를 기록 |
| `error` | `null` | 수락 시간 초과·RTC 참가 실패 | ACTIVE 전이 금지, 방·토큰 정리 |

## 최소 검증과 기대 결과

| 케이스 | 입력 또는 재현 조건 | 기대 결과 |
|---|---|---|
| 03.1 | 두 역할 실제 RTC 연결 완료 | `success` / `active`. 통화 상태 갱신, 동의 시 B-02 시작 |
| 03.2 | 사용자가 통화만 종료 | `success` / `ended`. RTC와 STT 정리, 도움 지속 여부는 N-11 판단 |
| 03.3 | 두 역할 연결 성공, 스피커 전환 실패 | `partial` / `route_fallback`. 시스템 오디오 경로 유지, 실패를 기록 |
| 03.4 | 수락 시간 초과·RTC 참가 실패 | `error` / `null`. ACTIVE 전이 금지, 방·토큰 정리 |
| 03.5 | 경계 재현 · 두 AVD에서 통화와 통화 끊기 | `diagnostic.basis`가 호출의 입력 스코프와 일치한다. 동일 `run_id` 추적으로 위 반환 분류 및 구현 완료 기준을 확인한다. |
