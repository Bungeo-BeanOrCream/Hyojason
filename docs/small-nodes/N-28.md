# N-28 · assess_instruction_follow_through

- **위치와 담당** Agent 서버 · C, 화면 증거 A
- **상위 노드** [B-05](../big-nodes/B-05.md)
- **상태** 계약 확정. 구현 및 실험 전.

실제 화면 전이 단서로 부모가 그 지시대로 조작했는지 판단한다.

## 호출 조건

CALL_CHILD_LED의 새 관측 결과가 해당 지시 이후의 검증 가능한 화면 변화일 때.

## 입출력 계약

다음 표는 노드 입력과 `NodeResult.data`의 필수 키다. [공통 결과와 Diagnostic](../node-result-contract.md)을 적용한다.

### 입력

| 필드 | 타입 | null |
|---|---|---|
| `instruction` | `Instruction` | 불가 |
| `before` | `ScreenState` | 불가 |
| `after` | `ScreenState` | 불가 |
| `target` | `TargetDecision` | 허용 |
| `basis` | `Basis` | 불가 |

### 결과 데이터

| 필드 | 타입 | null |
|---|---|---|
| `verdict` | `enum` | 불가 |
| `instruction_revision` | `int` | 불가 |
| `from_screen_revision` | `int` | 불가 |
| `to_screen_revision` | `int` | 불가 |
| `evidence_codes` | `enum[]` | 불가 |
| `model_revision` | `str` | 허용 |

## 고정 워크플로우

~~~mermaid
flowchart TD
    start(["N-28 호출"]) --> valid{"모드, 권한, 관련 Basis가 유효한가?"}
    valid -->|유효| prepare["현재 지시와 연속 관측의 변화 종류 검증"]
    valid -->|무효| rejected["오류 또는 소속된 정책 결과"]
    prepare --> decide["N-14 ACTION_MATCH 후 근거·버전과 선택 대조"]
    decide --> checked{"맞는 조작 또는 오선택을 입증했는가?"}
    checked -->|확인| result["검증된 결과와 실행 근거"]
    checked -->|미확인| wait["명시적 보류·부분·오류 결과"]
    rejected --> envelope(["NodeResult"])
    result --> envelope
    wait --> envelope
~~~

- 지시된 조작의 기대 전이/상태와 before·after 차이를 입력한다. 단순 스크롤, 시스템 변경, 프레임 공백, 실제 터치 여부가 불확실한 경우는 증거 없이 WRONG으로 승격하지 않는다.
- 검증 가능한 변화가 시작되면 부모 게이트는 결과 수신 전 대기한다. 관측이 연속인데 변화가 없는 경우에는 모델을 매 프레임 호출하지 않는다.
- WRONG은 지원 앱에서 직접 반대 선택이 입증된 경우다. BACK 가이드는 별도의 검증된 역엣지가 있어야 한다. scrolled/back으로 지시를 복구한 상태는 같은 지시를 다시 탐색한다.

## 반환 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `followed` | 대상 조작의 기대 전이와 모델 판단 일치 | 같은 지시 닫고 표시 제거 |
| `success` | `wrong_action` | 검증된 다른 조작, 최신 지시 | N-16에서 원래 화면 복귀 엣지 검사 |
| `success` | `not_established` | 관측 공백·중간 변화·모호한 증거 | verdict=UNKNOWN. 오선택·무입력 단정 금지 |
| `error` | `null` | 입력·스코프·모델 처리 오류 | 검증된 수행 결과가 없어 표시 보류 |
