# N-17 · choose_post_call_action

- **위치와 담당** Agent 서버 · C
- **상위 노드** [B-05](../big-nodes/B-05.md)
- **상태** 계약 확정. 구현 및 실험 전.

통화 후 유효 목표로 가는 가장 가까운 검증 경로에서 행동 하나를 고른다.

## 호출 조건

POST_CALL_AGENT이고 도착이 확정되지 않았으며 N-16에 사용할 수 있는 후보가 있을 때.

## 입출력 계약

다음 표는 노드 입력과 `NodeResult.data`의 필수 키다. [공통 결과와 Diagnostic](../node-result-contract.md)을 적용한다.

### 입력

| 필드 | 타입 | null |
|---|---|---|
| `candidate_set` | `CandidateSet` | 불가 |
| `goal` | `Goal` | 불가 |
| `basis` | `Basis` | 불가 |
| `threshold_profile` | `str` | 불가 |

### 결과 데이터

| 필드 | 타입 | null |
|---|---|---|
| `proposal` | `GuideProposal` | 허용 |
| `reason` | `enum` | 불가 |
| `model_revision` | `str` | 허용 |
| `selected_id` | `str` | 허용 |

## 고정 워크플로우

~~~mermaid
flowchart TD
    start(["N-17 호출"]) --> valid{"모드, 권한, 관련 Basis가 유효한가?"}
    valid -->|유효| prepare["현재 가장 가까운 검증 경로와 안전한 선택지 구성"]
    valid -->|무효| rejected["오류 또는 소속된 정책 결과"]
    prepare --> decide["N-14 NEXT_ACTION 호출 후 버전·임계값 검사"]
    decide --> checked{"유효 제안인가?"}
    checked -->|확인| result["검증된 결과와 실행 근거"]
    checked -->|미확인| wait["명시적 보류·부분·오류 결과"]
    rejected --> envelope(["NodeResult"])
    result --> envelope
    wait --> envelope
~~~

- N-16의 근거로 경로가 더 긴 복귀·순환을 제거하고 동일 거리의 현재 합법 행동에서 실제 모델이 선택한다. 입력 값은 승인된 목표 슬롯에서만 가져온다.
- 목표에서 할 일을 추정하는 greedy 방식은 통화 후 전용이다. 통화 중에는 호출하지 않는다.
- 빈 후보, 부분 검색의 역경로, 무효 화면에서 표시 제안을 만들지 않는다. 제안은 ID만 담고 부모 앱에서 로컬 위치를 해석한다.

## 반환 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `proposed` | 승인된 현재 행동과 모델 확신 유효 | B-06 통화 후 게이트에 전달 |
| `success` | `waiting` | 불충분한 근거 또는 확신 미달 | 현재 대상 표시 없음 |
| `error` | `null` | CALL_CHILD_LED, STALE_BASIS, 모델 타임아웃 | 모델 무응답을 임의 자동 경로로 대체하지 않음 |
