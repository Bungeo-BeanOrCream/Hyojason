# N-16 · enumerate_action_candidates

- **위치와 담당** C · Agent 서버, D 프로필
- **상위 노드** [B-05](../big-nodes/B-05.md)
- **상태** 설계. 구현 및 시연 환경 검증 필요.

현재 화면과 관찰 이력에서 합법적인 다음 행동 후보를 구성한다.

| 경계 | 계약 |
|---|---|
| 입력 | 최신 ScreenState, goal 및 슬롯, NavigationTrail, 위험 정책 |
| 출력 | CandidateSet(visible_choices, recovery_choices, policy_denials) |

## 처리 규칙

- 현재 화면에서 실제로 확인한 target과 조작만 후보에 넣는다. 화면 레지스트리는 라벨, 컨트롤, 완료 단서를 설명하고, 화면별 행동은 후속 탐지·판단 때 고른다.
- 최근 이력의 검증된 역방향 엣지를 따라 후보를 좁힌다. 현재 화면에서 직접 목표로 이어지는 후보가 없으면 실제 방문했던 가까운 상태로 돌아가는 BACK을 추가한다.
- 삭제·공장 초기화·신원 인증·모르는 수신자/URL과 주문/송금 등 지원 목표 밖 입력을 허용 목록에 넣지 않는다. 사용자 슬롯은 표시 목적에만 사용한다.

## 오류 및 보류

홈 화면/앱 위치가 확인되지 않으면 WAIT 또는 확인 요청만 가능. 보호 화면 다루는 후보는 비어 있어야 한다.

## 구현 완료 기준

표시 크기 및 텍스트에서 목표 변경 시 BACK 후보가 있고, 화면 공백 이력만 있는 경우 검증된 BACK 예측을 제공하지 않는다.
