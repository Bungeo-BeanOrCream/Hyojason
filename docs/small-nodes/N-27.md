# N-27 · locate_child_instruction_target

- **위치와 담당** Agent 서버·부모 로컬 매칭 · C/A
- **상위 노드** [B-05](../big-nodes/B-05.md)
- **상태** 계약 확정. 구현 및 실험 전.

자녀가 말한 버튼의 승인 대상과 위치 범위를 3초 동안 미리 찾는다.

## 호출 조건

CALL_CHILD_LED, 활성 지시와 최신 안정 화면, N-16의 유효 직접·아래 후보가 있을 때.

## 입출력 계약

다음 표는 노드 입력과 `NodeResult.data`의 필수 키다. [공통 결과와 Diagnostic](../node-result-contract.md)을 적용한다.

## 고정 워크플로우

~~~mermaid
flowchart TD
    start(["N-27 호출"]) --> valid{"모드, 권한, 관련 Basis가 유효한가?"}
    valid -->|유효| prepare["지시 라벨·동의어를 화면 후보와 매핑"]
    valid -->|무효| rejected["오류 또는 소속된 정책 결과"]

    decide --> checked{"현재 지시의 위치를 입증했나?"}
    checked -->|확인| result["검증된 결과와 실행 근거"]
    checked -->|미확인| wait["명시적 보류·부분·오류 결과"]
    rejected --> envelope(["NodeResult"])
    result --> envelope
    wait --> envelope
~~~

- 모델은 위치의 후보 ID를 고르고 좌표는 부모 로컬에서 현재 target_id와 layout을 일치시킨다. 지시를 받으면 타이머와 독립적으로 작업한다.
- 현재 보이는 버튼과 화면 아래 버튼을 구분한다. 아래는 스크롤 컨테이너의 근거가 없으면 UNKNOWN. 다른 지시·모드·화면의 늦은 위치는 N-19로 발행하지 않는다.
