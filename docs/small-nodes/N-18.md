# N-18 · assess_post_call_arrival

- **위치와 담당** Agent 서버 · C
- **상위 노드** [B-05](../big-nodes/B-05.md)
- **상태** 계약 확정. 구현 및 실험 전.

통화 후 목표의 화면 도착 사실을 추정한다.

## 호출 조건

POST_CALL_AGENT의 최신 안정 화면에 목표별 도착 단서가 있을 때.

## 입출력 계약

다음 표는 노드 입력과 `NodeResult.data`의 필수 키다. [공통 결과와 Diagnostic](../node-result-contract.md)을 적용한다.

### 입력

| 필드 | 타입 | null |
|---|---|---|
| `goal` | `Goal` | 불가 |
| `screen` | `ScreenState` | 불가 |
| `evidence_codes` | `enum[]` | 불가 |
| `basis` | `Basis` | 불가 |

### 결과 데이터

| 필드 | 타입 | null |
|---|---|---|
| `arrived` | `bool` | 불가 |
| `evidence_codes` | `enum[]` | 불가 |
| `confidence` | `number` | 허용 |
| `arrival_id` | `str` | 허용 |

## 고정 워크플로우

~~~mermaid
flowchart TD
    start(["N-18 호출"]) --> valid{"모드, 권한, 관련 Basis가 유효한가?"}
    valid -->|유효| prepare["목표별 필수 완료 증거·슬롯 대조"]
    valid -->|무효| rejected["오류 또는 소속된 정책 결과"]
    prepare --> decide["N-14 ARRIVAL 결과와 최신 화면 동시 검증"]
    decide --> checked{"목표 도착과 스코프를 확인했는가?"}
    checked -->|확인| result["검증된 결과와 실행 근거"]
    checked -->|미확인| wait["명시적 보류·부분·오류 결과"]
    rejected --> envelope(["NodeResult"])
    result --> envelope
    wait --> envelope
~~~

- 필수 증거가 없다면 모델을 호출하지 않는다. 임계값과 화면 완료 규칙을 모두 통과해야 결과를 N-22에 전달한다.
- 알람은 시·분 외에 예상 울림 날짜와 활성 상태 확인이 필요하다. 문자 수신, 지도 길찾기, 지정 메일 열림은 [목표별 판정](../scenarios.md)을 따른다.
- 도착 추정은 자녀 알림이다. 부모·자녀의 도움 상태와 완료 권한은 N-22가 따로 처리한다.

## 반환 상태와 실패 처리

| 반환 상태 | 업무 결과 | 발생 조건 | 처리 원칙 |
|---|---|---|---|
| `success` | `arrival_suspected` | 화면 근거·모델 선택·버전 모두 유효 | N-22에서 도착 추정 1회 |
| `success` | `not_arrived` | 불충분/불일치 또는 확신 미달 | 필요시 N-17 고려. 모델 미호출이면 confidence=null |
| `error` | `null` | 잘못된 모드·스코프 또는 모델 실패 | 도착 알림 0회 |
