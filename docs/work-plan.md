# 4인 작업 배분과 통합 순서

작업 구간은 기술적 경계로 정의했다. 한 사람이 여러 Big Node를 맡을 수 있고, 공통 계약에 변경이 생기면 영향을 받는 소유자끼리 먼저 맞춘다. 실명 확정 전 역할 슬롯 A–D를 사용한다.

| 담당 | 주 소유 | 짝 작업 | 팀에게 넘길 결과 |
|---|---|---|---|
| A · Android 화면/입력 | B-03 화면 관찰, B-06 부모 안내 | D의 목표별 화면 목록을 AVD에서 검증, B의 전환 중 오디오를 본인 화면에서 시험 | Screens/targets 이벤트, 캡처와 Overlay 정확도, 부모의 화면과 안내 끄기 동작 |
| B · Android 통화/STT | B-01 연결·통화, B-02 발화 | D의 제어 채널과 참가·동의 상태를 합의, 자녀 마이크의 실제 입력 경로 검증 | 동일 APK에서 두 역할 실제 통화, 통화 중 STT, 끊은 뒤 STT 중지 |
| C · Zoro-1/인프라 | B-05 판단 | D가 정한 상태·옵션 계약에 맞는 adapter 및 B-08 모델·GPU 검증 | 실제 모델 실행 경로, 5종 판단과 확신, timeout/측정, 버전·비용 |
| D · 서버/통합/발표 | B-04 도움 상태·이력, B-07 피드백·종료, B-08 통합 검증 | A와 화면 상태·완료 증거, B와 독립 제어 채널, C와 통합 평가 | 세션 상태, 모드 인계와 완료 UX, 5개 앱 판정과 A/B 리허설 기록 |

## 첫 90분에 각자 동시에 만들 것

1. A는 두 AVD 기본 이미지와 부모 표시 권한을 준비하고, Settings 및 Clock에서 시험용 강조 아래 실제 터치가 전달되는지 확인한다. 캡처 중단과 동의 재시작을 실화면에서 확인한다.
2. B는 두 역할의 실제 통화를 연다. 같은 Mac의 마이크가 두 AVD에 같은 음성으로 전달되면, 역할별 음소거·분리 가능한 오디오 장치로 검증하고 경로를 문서화한다. RTC 종료 뒤 제어 채널은 살아 있는지 확인한다.
3. C는 크레딧 콘솔·모델 접근을 확인하고 L40S 한 대에서 고정 모델 revision으로 실제 Zoro 선택 5종을 작동시킨다. 모델 카드의 예시 출력이 실측값을 대신하지 않도록 로그를 남긴다.
4. D는 목표 ID, 화면 분류, 버전 필드, 완료 이벤트를 고정하고, A·B 화면의 메뉴와 백업 자료를 정리한다. 기능 코드는 담당 모듈별로 시작하며, 공동 경계 변경은 담당자끼리 맞춘다.

16시간 30분은 팀이 전달한 계획 기준이다. 시작 시간이 밀리면 남은 시간을 재확인하고 마지막 2시간을 먼저 확보한다.

| 경과 | 통과해야 다음 단계에 진입 |

| 01:30–05:00 | A 설정에서 자녀 지시 → 위치 탐색 → 마감 전 수행 검증 → 무표시 또는 개입까지 연결. 텍스트 입력으로 먼저 연결해도 되며 최종 라이브에서는 실제 음성 경로를 확인 |

| 12:00–14:30 | A·B 리허설 및 백업, 역할별 재현 순서 정리, 지시 20개·목표·위치·무오표시·GPU 사용 측정 |
| 14:30–16:30 | 기능 동결, 최종 리허설, 제출 자료와 발표 순서, 크레딧 확인 |

## 병목 시 보전 순서

- **유지:** 실제 Zoro-1, Android 외부 앱에서 3초 개입 및 빠른 정답 무표시, 지시·위치·연속 이력, 통화 후 도움 지속·자녀 완료.
- **우선 줄이기:** P1 여러 단계 지시 큐·추가 목표, 범용 인식·앱 전체 지원, 백그라운드 알림 시스템, 양쪽 상세 디버그 UI. 각 앱은 PRD P0 경로 하나씩 좁혀 검증한다.
- **명확하게 기록:** 음성 대신 시험용 텍스트, 화면 보호로 자녀 음성 안내, 목표 부족, 재접속, 모의 모델을 적용한 실행은 실제 라이브 성공과 분리한다. 실패한 P0를 완료 처리하지 않는다.

## 리허설 운영과 크레딧

C는 L40S 한 대, 운영 $80, 예비비 $20을 기준으로 시간당 전체 단가와 실제 차감량을 확인한다. 환경점검 $10, 개발·통합 $25, 평가 $15, 리허설 $15, 시연 $10, 적용 저장·전송 $5의 상한 계획이다. 총 $70에서 새 실험을 멈추고 마지막 시연 예산을 남긴다. Zoro 응답은 유의미한 사건부터 호출하고 화면 현지 처리는 단말에서 수행한다. RTC·STT 별도 비용도 기록한다.

발표에서는 A가 부모 앱, B가 자녀 앱, C가 실제 Zoro 모델 결과, D가 시나리오와 완료 증거를 맡는다. 앱 별 결과는 [실험 계획](verification-plan.md)에 남긴다.
